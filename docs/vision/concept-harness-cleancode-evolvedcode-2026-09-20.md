# 하네스 · 클린코드 · 진화코드: 3축 좌표계

> 생성일: 2026-09-20 · 출처: MCP 지식협력 미들웨어 스레드 아티팩트

## 결론
세 개념은 위계 관계가 아니라 **서로 다른 실패모드를 각자 담당**하는 병렬 요인이다.
2026년 5월 발표된 660건 규모 Claude Code 통제실험이 이를 실증한다: 코드 클린니스는
"모델 선택, 하네스, 프롬프팅과 나란히 에이전트 행동에 영향을 미치는 요인"으로 합류한다.

## 3축 비교표

| 키워드 | 무엇을 통제하는가 | 무엇을 통제하지 못하는가 | 스택 레이어 |
|---|---|---|---|
| 하네스 | 컨텍스트 오버플로우, 목표 상실, 검증 게이트 | 코드 자체의 품질이나 최적성 | Layer2 (Harness Gate) |
| 클린코드 | 토큰 효율, 파일 재방문 비용, 탐색 비용 | 정답률(pass rate) 자체는 불변 | Layer2 (Harness Gate) |
| 진화코드 | 객관적 지표 기준 알고리즘 최적성 | 평가함수가 없는 주관적/가독성 목표 | Layer4 (Evolution Loop) |

## 클린코드: 재정의된 기준
- 함수 4~20줄, 파일 500줄 이하 (이상 200~300줄)
- 코드베이스 전체 grep 결과 5건 미만인 구체적 네이밍
- `any`/`Dict` 같은 무형식 타입 금지
- 정답률 불변, 토큰 7~8% 절감, 파일 재방문 34% 감소 (660건 실험)
- 에이전트는 클린 저장소에서도 스타일만 모방, 아키텍처 의도는 CLAUDE.md로 명시 필요

## 진화코드: AlphaEvolve/CodeEvolve 계보
- 씨드 프로그램 + 평가함수 → Gemini Flash(다양성)/Pro(깊이) 변이 제안 → 컴파일-실행-평가 검증
- 정답성 유지 + 목표 지표(속도/메모리) 개선 변이만 다음 세대 부모로 선택
- 제약: "코드를 더 깔끔하게" 같은 모호한 목표는 불가, 반드시 검증 가능한 성공 상태 필요

## 스택 통합 권고
- **Layer2 (하네스 게이트)**: 클린코드 린트 규칙을 검증 조건으로 추가
- **Layer4 (진화 루프)**: 평가함수에 토큰 소비량·파일 재방문 수 포함
